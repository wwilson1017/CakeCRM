## Tooling

- `[✓1 ✗0 · 2026-07-23]` **When** running `ruff` while a sibling PR owns the repo's lint config (`ruff.toml` not yet merged) → **do** run `ruff check --config <that file>` scoped to YOUR files, never `ruff check . --fix` tree-wide → **because** default ruff selects far more rules than the repo config (`F,E,W,I` here), and a tree-wide `--fix` re-sorts imports in files outside your change, creating spurious diffs that conflict with the sibling PR. - `[✓0 ✗0 · 2026-07-25]` **When** committing via `git add <explicit list>` in an automated flow → **do** NOT suppress stderr (`2>/dev/null`), and verify with `git show --stat <sha>` (or a clean `git status`) that the commit captured what you intended → **because** one stale/nonexistent pathspec (e.g. an old path after a `git mv`) aborts the ENTIRE add; with stderr hidden the "commit" silently captured only what was already staged, while tests kept passing against the WORKING TREE — the drop was invisible until the Stage-4 reviewer found uncommitted fixes including a P1 (#16/PR #45).
- `[✓0 ✗0 · 2026-07-27]` **When** a docstring or comment asserts a resource is "bounded" / "safe" / "eventually cleans itself up" NEXT TO concurrency, socket, thread, or lock code → **do** treat the claim as a hypothesis to DISPROVE — construct the exact scenario in which it does not hold — before letting it stand → **because** on #17/PR #51 a docstring claimed a leaked scan worker was "bounded — the socket eventually errors", and that false assumption is precisely what let an **unbounded** thread+socket leak (one per scan interval under a persistent transport hang) ship looking safe through review-super AND the first Codex pass. Without a transport timeout a stalled socket may never error, so "eventually" was never guaranteed.
