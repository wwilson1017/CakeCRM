CakeCRM is a free, self-hostable CRM with a built-in AI sales assistant called Baker. The CRM is the product and Baker is one feature of it: every part of the CRM works with no AI provider connected. AI features stay hidden until an admin connects one, and they never show errors in the meantime.

How the pieces fit

The navigation has six destinations, and each one answers a different question.

Destination What it is for
Dashboard What needs you today, and how the pipeline looks overall
Pipeline Your deals, by stage, as a board or a list
Contacts The people you sell to
Companies The organisations they belong to
Todos Your follow-ups, the one follow-up tool in the product
Reports Everything known about one company, on one page

A typical loop: create a contact, create a deal linked to it, log an activity against the deal, and add a follow-up todo. That loop is the whole CRM in miniature. Start with What CakeCRM is if you are new.

Baker sits in the bottom-right corner of every page. Once an admin connects an AI provider it can read your CRM, make changes for you, and answer questions about your pipeline. You choose how much it asks first: see Approvals and modes. See Meet Baker.

Admins and members

There are exactly two roles.

  • Members can do everything with CRM records: create, edit and close deals, contacts, companies and todos. Owning a record is not a permission; any member may edit any record.
  • Admins can also change how the install is set up: branding, the team, custom fields, integrations, the todo mode, AI providers and Baker's protected memory files.

In Settings, members see the Personal and Assistant sections; Workspace and Integrations are admin-only and do not appear for a member. Where a page in this manual describes something only an admin can do, it says so.

Running your own copy

If you are installing CakeCRM rather than using an existing install, start with Deploying and The first admin and passwords.

Manual › Getting started

What CakeCRM is

A free, self-hostable CRM with an AI assistant built in, and a CRM that works fully without it.

CakeCRM is a free, open-source CRM you run on your own server. It keeps your contacts, companies, deals and follow-up todos in one place, and it comes with a built-in AI sales assistant called Baker.

The CRM comes first

Every part of the CRM works with no AI provider configured. Lead scores, duplicate scans, deal staleness, the dashboard, analytics and the company report are plain database work and are always available.

What stays hidden until an admin connects a provider:

  • Baker's chat itself.
  • Assisted import of file formats beyond CSV and vCard.
  • The estimated touch-count pill on deal cards, and the Weekly touches card on the dashboard.
  • AI provenance badges.

These hide rather than break. You never see an error because no key is set. An admin may see a dismissible banner offering to add a key; it is a prompt, never a gate, and dismissing it is remembered.

Where things live

Page What you find there
Dashboard A Today panel ranking what needs you now, headline counts, a snapshot and recent activity
Pipeline The deal board, by stage, with a list view and filters
Contacts and Companies Searchable lists with detail pages that roll up linked records, notes and activity
Todos Your follow-ups
Reports One report: everything known about a single company
Settings Personal, Assistant, Workspace and Integrations

Your first ten minutes

  1. Sign in.
  2. If the CRM is empty, you are offered sample data: fictional contacts, deals and todos so you can see how everything behaves.
  3. Walk the navigation: Dashboard, Pipeline, Contacts, Companies, Todos, Reports.
  4. Create a contact, create a deal linked to it, log an activity against the deal, and add a follow-up todo.

Adding AI

An admin connects a provider and a model on the AI Setup page. Once a key is connected, the Baker button in the bottom-right corner opens a chat drawer instead of pointing at setup. See AI setup.

Signing in

Sign in with your email and password, and what happens when your account has two-factor turned on.

Open your install's address (for example https://crm.example.com) and you land on the sign-in screen.

Signing in

  1. Enter your Email and Password.
  2. Press Sign in.

You arrive on the Dashboard. Your account is created by an admin from Settings, Workspace, Team; there is no sign-up form. On a brand-new install, the first admin account is created by the server from its environment settings. See The first admin and passwords.

Two-factor codes

If two-factor authentication is switched on for your account, a second screen asks for a code after your password.

  • Enter the 6-digit code from your authenticator app and press Verify.
  • Lost your phone? Press Use a backup code and enter one of your backup codes instead. Each backup code works once.
  • Tick Trust this browser for 30 days to skip the code on this browser for a month.
  • Back returns you to the password screen.

There is no screen in CakeCRM for turning two-factor on, showing a QR code or listing backup codes. The server supports it, but the setup screen has not been built.

Signing out

Press Sign out at the top right of any page. On a phone it is at the bottom of the menu; see Using CakeCRM on a phone.

Forgotten passwords

There is no emailed reset link: a self-hosted install has no mail server to send one.

  • A member who has forgotten their password asks an admin, who resets it from Settings, Workspace, Team. If they have also lost their authenticator, the admin can tick the box that clears two-factor at the same time.
  • The only admin needs whoever runs the server to set a password-reset value in its environment. See The first admin and passwords.

To change a password you still know, use Settings, Personal, Change password. Changing it signs you out everywhere else and keeps you signed in where you are. See Personal settings.

Sample data

Load a fictional set of contacts, deals and todos to explore CakeCRM, then clear it when you are ready for real records.

A brand-new CRM is empty, which makes it hard to see how anything behaves. CakeCRM can fill it with fictional sample data: a small business with its contacts, companies, deals and todos. Every name in it is made up.

Loading it

When the CRM has no records, a Start with sample data? dialog appears after you sign in. You have two choices:

  • Load sample data fills the CRM with the examples. Loading needs an admin account.
  • No thanks, start fresh closes the dialog and leaves the CRM empty. The choice is remembered for the whole install, so the dialog does not come back.

The example-data banner

While sample data is loaded, admins see a banner across the top of every page: "You're viewing example data — contacts, deals, and todos are samples." It stays there so nobody mistakes the examples for real records.

Clearing it

Press Clear example data in the banner. A confirmation asks Clear all CRM data?, and you press Clear everything to go ahead.

Read that confirmation carefully. Clearing removes the example data and anything you have added since. It cannot be undone. If you want to try CakeCRM with sample data and then go live, clear the samples before you start entering real records.

What clearing keeps:

  • Everyone's user accounts.
  • Custom field definitions an admin has set up.
  • Saved views on list pages.

Custom stage criteria on the pipeline are put back to the standard ones. See Stages and closing a deal.

Only admins see the banner and its Clear button; clearing changes the whole install.

Using CakeCRM on a phone

The same CRM in a narrower layout, with a menu drawer and a few touch-friendly changes.

CakeCRM works in your phone's browser. There is nothing to install; open the same address you use on a computer and sign in.

Getting around

On a narrow screen the header changes:

  • A row of tabs under the header holds the six destinations: Dashboard, Pipeline, Contacts, Companies, Todos and Reports. Swipe it sideways if they do not all fit.
  • The light/dark switch and the notifications bell stay in the header, so alerts are always one tap away.
  • The menu button (three lines, top left) opens the Menu drawer.

The drawer lists the same six destinations plus Settings, AI Setup (admins only) and Sign out. Tap the × to close it.

The pipeline on a phone

The board shows roughly one stage column at a time, and you swipe between them. A row of stage pills above the board jumps straight to a column and shows which one you are on.

Some desktop actions work differently on a phone:

  • No dragging. To move a deal to another stage, open it and use Edit, or Mark Won or Mark Lost.
  • No checkboxes, so there is no bulk move. Use a computer for moving deals in bulk.
  • The Add Deal button reads Add.
  • A stage's checklist opens as a sheet along the bottom of the screen rather than a panel in the corner.

Baker on a phone

The Baker button sits in the bottom-right corner on a phone too. Pages leave room at the bottom so you can scroll past it.

Light and dark mode

Switch between a light and a dark theme with one button; CakeCRM follows your device until you choose.

CakeCRM has a light theme and a dark theme. Every page works the same in both; only the look changes.

Switching

Press the sun or moon button in the header, beside the notifications bell. It is in the header on a phone as well.

  • In light mode the button shows a moon and switches you to dark.
  • In dark mode it shows a sun and switches you to light.

How CakeCRM picks a theme

Until you press the button, CakeCRM follows your device's own setting. If your computer switches to dark mode in the evening, CakeCRM switches with it.

Once you press the button, your choice wins and stays put. It is saved in this browser, so:

  • Other tabs of CakeCRM open in the same browser switch along with it.
  • Another browser or another device keeps its own setting.
  • If your browser blocks site storage, the choice lasts until you close the tab.

The theme is a personal display choice. It does not affect anyone else on your team.

Notifications

The bell, browser push, Telegram and the daily digest, and what raises a notification in the first place.

CakeCRM tells you when something needs you through the bell in the header, and optionally through browser push and Telegram. None of it needs an AI provider.

The bell

The bell sits in the header on every page, on a phone too. Its badge counts your unread notifications. Open it to read them, dismiss one with its ✕, or clear the lot with Dismiss all.

When the system itself has a problem to report, an alert appears at the top of the list with Acknowledge and Resolve buttons. Alerts are shared by the whole install.

Who sees a notification

Every notification is one of two kinds.

  • Addressed to you. Nobody else sees it, and nobody else can dismiss it. A mention, or a nudge about a deal or contact you own, is the usual case.
  • Sent to everyone. The daily digest, anything Baker raises while working in the background, and a nudge about a record with no owner. Dismissing one of these dismisses it for the whole team.

What raises a notification

  • Mentions. A teammate types @ in a note on a deal, contact or company and picks your name. The notification's title opens that record. See Notes, mentions and attachments.
  • The daily digest and nudges, when an admin has turned them on (below).
  • Baker, at most one notification per background run, once an AI provider is connected.

Browser push

In Settings, Personal, the Notifications card has Enable Web Push. Pressing it asks your browser for permission and registers this browser. It works per browser and per device: turning it on at your desk does nothing for your phone. Disable Web Push turns it off again.

If your browser has blocked notifications for the site, the card says so; allow them in your browser's settings first.

Send test notification sends a real notification through the whole delivery path and tells you whether it reached a device or only landed in the bell.

Telegram

If you link your Telegram account from Settings, Personal, Link my Telegram, your notifications also go to that chat. There is no separate on/off switch for it. See Telegram.

The daily digest and nudges (admins)

The same card has a Daily digest and nudges section with Turn on and Turn off. It sends a pipeline summary each morning, plus a nudge when a deal goes cold or a contact with open business has not been spoken to. It applies to the whole install, so only admins see the control.

The dashboard

The first page after you sign in: what needs you today, then the shape of the pipeline and recent work.

The Dashboard is the first page you see after signing in. It reads from top to bottom: first what needs you now, then how the pipeline looks, then what has happened lately. Everything on it is plain database work and works with no AI provider.

The headline

At the top, "Pipeline is ..." gives the total value of your open deals and how many there are. Open means any deal in lead, qualified, proposal or negotiation.

Today

Directly under the headline, the Today panel lists up to five things that need you now: starred todos, hot deals that have gone quiet, overdue todos and todos due today. See The Today panel.

The four counts

Four tiles are always there: Contacts, Companies, Pipeline value and Overdue todos (with the number of pending todos underneath).

Snapshot

Tile What it shows
Win rate Won deals as a share of all closed deals, with the won and lost counts
Avg days to close Roughly how long won deals took
Avg won deal The average value of a won deal
Open deals How many deals are open, and what they are worth

A bar under the tiles splits won from lost. With nothing closed yet it reads "No closed deals yet."

Weekly touches

Once an AI provider is connected, a Weekly touches card shows how many open deals each person touched in the week. A touch is an edit, a logged activity or a note. With no provider the card is not shown.

Stages

One row per open stage, with its value and number of deals. Click a row to open the Pipeline board scrolled to that stage's column. Any filters you had on the board are cleared so the column is in view.

Further down

  • By rep: each person's open deals, pipeline, won and lost, records touched and activity over the last 30 days. It only appears when more than one person uses the install.
  • Deal aging: open deals grouped by age, and Needs a touch: open deals with nothing logged for 14 days or more. Click one to open it.
  • Activity: how much was logged in the last 30 days, by day and by type.
  • Top deals: the five largest open deals past the lead stage. Click one to open it in place. See Deal health and scores for how they are picked.
  • Recent activity: the last ten activities logged anywhere.

At the bottom, + Add Contact, + Add Deal and + Add Todo take you to the page where you add each one.

The Today panel

One short, ranked list at the top of the dashboard of what needs you today.

The Today panel sits at the top of the Dashboard. It answers one question: what should I do now? It is ranked by plain rules, not AI, and works the same with or without an AI provider.

What goes on it, in order

  1. Starred todos you have marked for today.
  2. Hot deals that have gone quiet: deals you have marked hot that have had no touch for 14 days or more. At most two take a slot, longest-quiet first, so a neglected pipeline never buries the promises you made yourself.
  3. Overdue todos.
  4. Todos due today.

Each todo row wears a label saying why it is there: STARRED, OVERDUE or DUE TODAY. A deal row shows its hot icon and how long it has been idle and what it is worth, for example "idle 12d · $30K".

Five at a time

The panel shows up to five rows. If more are waiting, +N more today opens the rest and Show less folds them away again. The extra rows also include:

  • Hot deals that are still being worked, and quiet hot deals beyond the first two.
  • Todos marked BROUGHT BACK, whose bring-back date has arrived.

When nothing is ranked, the panel reads "Nothing needs you today."

Acting on a row

  • Tick the box on a todo row to complete it without leaving the dashboard.
  • Click a todo's title to go to Todos.
  • Click a deal to open it on the Pipeline.

Marking a deal hot is up to you; see Deal health and scores.

Mine and Everyone

On an install with more than one person, MINE and EVERYONE buttons sit beside the heading. Mine shows your own work plus anything with no owner, so unassigned work is always caught by someone; those rows are labelled Unassigned. Everyone shows the whole team. Your choice is remembered in this browser tab.

When it updates

The panel uses the install's own day, not your computer's, and reloads itself at midnight.

The pipeline board

Every deal as a card in its stage's column; drag a card to move it, click it to open it.

Pipeline shows your deals as cards in columns, one column per stage. Under the page title a line reads how much is open and how many open deals there are.

The columns

There are six stages: lead, qualified, proposal, negotiation, won and lost. The board opens with the four open stages showing. Won and Lost are hidden by default, so the board is about work that is still live.

When any stage is hidden, the line under the title says how many, with a Show all link beside it. Nothing is ever secretly missing. To hide or show a single column, use the stage checkboxes in the toolbar above the board. See Stages and closing a deal for how to make Won and Lost show by default.

What a card shows

  • The deal title and its value.
  • The linked contact.
  • The probability, if one is set.
  • The forecasted close date, or "No forecast date".
  • A lead score, an estimated touch count (only with an AI provider) and a temperature icon you can click to mark the deal hot, warm or cold.

On a Won card, the score, touch count and temperature are replaced by when the account was last contacted, because after the sale the question is whether it has gone quiet.

See Deal health and scores for what the numbers mean.

Moving a deal

Drag a card into another column. The move saves straight away. Dragging still works while a filter is on.

Dragging into Won records today as the deal's Closed on date, and dragging into Lost records no reason. To capture the real close date or a lost reason, open the deal and use Mark Won or Mark Lost instead. See Stages and closing a deal.

On a phone there is no dragging; open the deal instead. See Using CakeCRM on a phone.

Opening a deal

Click a card to open the deal in a panel over the board. See The deal page.

Searching and filtering

The search box above the board matches deal titles, contact names and company names. Filters narrows the board by stage, owner, value, dates, activity and more. Board and List switch between this view and a table. See List, filters and saved views.

Adding a deal

Press Add Deal at the top right. See Adding a deal.

List, filters and saved views

See deals as a sortable table, narrow them with filters, and save a filtered view for the whole team.

The toolbar above the pipeline has a search box, a Filters button, a Sort control, the Board and List switch, the stage checkboxes and a Views menu.

The list view

Press List to see your deals as a table.

The columns are Deal, Company, Stage, Value, % Closed, Score, Touches, Forecasted close, Closed on, Last activity and Owner. Click a row to open the deal. The Touches column needs an AI provider and is empty without one.

Sorting

Sort orders the deals by Board order, Deal, Company, Value, % Closed, Lead score, Touches, Forecasted close date, Closed on, Last activity or Owner. The arrow beside it flips between ascending and descending.

Filters

Press Filters to open the filter panel. The button shows how many filters are on, for example "Filters (2)", and Clear filters turns them all off along with the search.

Filters, search and sort are remembered for this browser tab.

Saved views

A saved view stores the filters, search text, sort and Board or List choice under a name, so you can come back to it in one click. Saved views are shared: everyone on the team sees and can apply every view.

  1. Set up the filters you want.
  2. Open Views and press Save current view.
  3. Type a name and press Save.

To use a view, open Views and click its name. Each view shows who made it.

Only the person who made a view, or an admin, can change it. They see Update to current view (replace it with what is on screen now), Rename and Delete. Updating or deleting changes it for everyone.

Saved views do not include which stage columns you have hidden; that stays your own choice on your own device. A view saved under an older version of the page is listed but greyed out, with a note saying so.

The deal page

Everything about one deal in a single panel: its details, how to edit or close it, the activity log and the notes thread.

Click a deal anywhere in CakeCRM (a board card, a list row, a Top deals row on the dashboard) and it opens in a panel over the page.

Along the top

Button What it does
Copy link Copies a link that opens this deal on the Pipeline, to paste into a message or a note
Edit Turns the panel into a form so you can change the deal's fields
Mark Won Closes the deal as won, asking which day it closed
Mark Lost Closes the deal as lost, asking for a reason
Archive Hides a duplicate or junk deal, asking for a reason. See Archived deals

Mark Won and Mark Lost only appear while the deal is in an open stage. Archive appears on any deal that is not already archived. See Stages and closing a deal.

The details

Under the title and value you see the stage, then the Deal ID, Contact, Company, Owner, Temperature, Probability, Lead Score, Forecasted close date and Closed on. A lost deal also shows its LOST REASON.

Click the temperature icon to cycle the deal through hot, warm, cold and not set. Once an AI provider is connected, an estimated touch count also appears here, and you can open the line-by-line reasons behind it. See Deal health and scores.

Editing

Press Edit to change the title, contact, company, owner, stage, value, probability, forecasted close date or notes. A Won deal also shows its Closed on date here. Press Save to keep your changes or Cancel to drop them.

If you try to close the panel with unsaved changes, CakeCRM asks before throwing them away.

Log Activity

Pick call, email, meeting or note, type what happened in the box, and press Log. Clear puts the choice back if you picked one by mistake. An activity is a dated record of an interaction; it is history and is not edited afterwards.

Custom fields

If an admin has set up custom fields for deals, they appear under the activity box. See Custom fields.

Activity History

Every call, email, meeting and note logged against the deal.

Chatter

The notes thread at the bottom is for standing commentary about the deal. You can reply in threads, attach files and mention a teammate with @. See Notes, mentions and attachments.

Archived deals

An archived deal opens with a banner saying when it was archived, by whom and why, and a Restore button. See Archived deals.

Stages and closing a deal

The six stages, the checklist behind each one, and how to close a deal so the date and reason are kept.

The six stages

In order: lead, qualified, proposal, negotiation, won, lost. Lead through negotiation are the open stages; won and lost are the closed ones.

There is no preset probability per stage. A new deal starts at 0% unless you set one. Winning sets it to 100% and losing sets it to 0%.

Stage checklists

Every stage has a short summary and a checklist of what it takes for a deal to belong there.

  • Hover over a stage name on the board for a quick look.
  • Click it to pin the checklist in a small panel at the bottom-right of the screen (a sheet along the bottom on a phone). The board keeps working while it is open. Click another stage name to switch, or the same one, the ×, the panel itself or Escape to close it.

CakeCRM ships a Standard checklist for every stage. An admin can write their own: pin the stage, press Edit, change the summary, add, remove or reorder lines with Add item, then Save. The panel then shows Custom, and Reset to standard puts it back. Members see the checklists but not the Edit button. Custom checklists go back to standard when the CRM is reset or its sample data is cleared.

Won and Lost on the board

The board hides Won and Lost by default. Two separate controls decide this:

  • The stage checkboxes on the board hide or show a column for this browser tab only.
  • Settings, Personal, Pipeline board has a Show Won and Lost stages checkbox. That is the default every new tab starts from, saved in this browser.

Moving a deal into a hidden column shows that column, so a closed deal never vanishes without explanation.

Closing a deal properly

Open the deal and use Mark Won or Mark Lost. These are the only ways that keep the full record.

Mark Won asks When did this close? The Closed on day defaults to today. An earlier day is fine; a future day is refused. Press Confirm.

Mark Lost opens Mark as Lost with a Reason (optional) box, for example "Budget constraints, chose a competitor". Press Mark Lost. The reason is saved on the deal and written into its notes thread.

Every other way into Won or Lost (dragging a card, a bulk move, or changing the stage in the edit form) records today as the Closed on date and records no lost reason. A lost reason cannot be added later, and it is the most useful thing to have when you look back over a quarter, so it is worth the extra click.

The Closed on date

When a deal is won, the day it really closed is kept as its Closed on date, separate from the forecasted close date, which was only a guess. It shows on the deal, in the list view's Closed on column and in the Closed on filter.

  • While a deal is Won you can correct the date in the edit form, but you cannot blank it.
  • Every change leaves a "Closed on: old → new" note in the deal's notes thread.
  • Moving the deal out of Won clears the date; winning it again asks again.
  • Moving a deal out of Lost clears its lost reason.

Moving deals in bulk

Select several deals and move them to another stage in one go.

You can move many deals to a new stage at once. It is the only bulk action on the pipeline: there is no bulk archive, delete, close-with-reason, reassign or merge.

Doing it

  1. Tick the checkbox on each deal card, or on each row in the list view. In the list view, the box in the header selects every visible row.
  2. A bar appears reading how many deals are selected.
  3. Pick a stage from Move to… and press Apply.

There is no confirmation dialog. If you move deals to the wrong place, move them back. Clear drops the selection.

The selection only ever covers deals on screen, so what the bar counts and what Apply moves are always the same set. Checkboxes are not shown on a phone.

Limits

  • At most 200 deals per move. Selecting more is refused and nothing moves.
  • A deal already in the target stage is skipped and left untouched.
  • Archived deals have no checkbox and cannot be moved.
  • If a deal in the selection has gone or been archived in the meantime, CakeCRM tells you which one and still moves the rest.

Moving into Won or Lost

Move to… does list Won and Lost, but a bulk move closes the deals with today as their Closed on date and no lost reason. If the date or reason matters, close the deals one at a time with Mark Won or Mark Lost. See Stages and closing a deal.

Asking Baker

With an AI provider connected, you can ask Baker to move a set of deals. It has the same 200-deal limit, but it only moves deals into open stages. It refuses to win or lose deals in bulk, and closes them one at a time instead so each date and reason is captured. See What Baker can do.

Archived deals

Archiving hides a junk deal without deleting it, and Restore brings it back.

Archiving is a soft hide. The deal keeps every note, activity and todo; it simply stops appearing. Nothing is deleted.

Archived is not Lost

  • Lost is a real outcome: the deal happened and you did not win it. It counts in your win rate.
  • Archived means "stop showing me this": a duplicate, a test record, something created by mistake.

Never archive a deal that genuinely closed. Use Mark Lost instead.

How to archive a deal

Open the deal and press Archive, next to Mark Won and Mark Lost. It is there on any deal that is not already archived, open or closed. Archiving always needs a reason: the dialog will not submit without one. The reason and your name are saved on the deal and written into its notes as "Archived — reason".

Baker can archive a deal too, once an AI provider is connected. In Ask mode it shows an Approve card first; see Approvals.

Merging two deals archives the one merged away, with the reason "Merged into deal #N".

Where an archived deal goes

It leaves the board, the dashboard, analytics, the deal lists, and the contact and company pages. Its open todos drop out of your todo lists too.

Its activity history is never hidden, because that is what you read to decide whether to bring it back.

Finding and restoring one

  1. On the Pipeline, open Filters and set Archived to Include archived or Archived only. If the board is empty, a Show archived deals link appears under the page title instead.
  2. Archived cards are dimmed and marked ARCHIVED. They cannot be dragged or selected, but they still open.
  3. Open the deal. A banner says when it was archived, by whom and why. Press Restore.

Restoring puts the deal straight back on the board and leaves a "Restored from archive." note with your name. Neither the archive nor the restore note counts as contact with the customer, so they do not reset how long the deal has gone untouched.

While a deal is archived

  • Its stage cannot be changed, and it has no Mark Won or Mark Lost buttons.
  • It cannot be part of a bulk move.
  • Archiving it again keeps the original date, person and reason.

Restoring a merged deal

Restoring a deal that was merged away makes it visible again, but it does not undo the merge. Its activity and todos already moved to the deal it was merged into, and they stay there.

Deal health and scores

What the lead score, temperature and touch count on a deal mean, and which of them need AI.

A deal card carries up to three signals. Two of them are plain arithmetic or your own judgement and always work; one needs an AI provider.

The lead score

A number from 0 to 100 on every deal (and every contact). It is pure arithmetic with no AI involved. For a deal it starts from a baseline for the current stage and adjusts it for:

  • engagement: how much has been logged against it;
  • value: the size of the deal;
  • relationship: whether it is linked to a contact and a company;
  • recency: how long since the last touch;
  • age: how long since it was created;
  • temperature: your own read on it, below.

An open deal always scores between 1 and 99. A won deal is exactly 100 and a lost one exactly 0. Nobody can type a score in, and neither can Baker. It is recalculated when the deal changes and refreshed daily.

On its own the score tells you little you can act on. Use it to sort, then look at what the deal needs.

Temperature

Your own judgement, with three values: hot, warm and cold, plus not set. Not set is neutral: it is not the same as cold and does not lower the score.

Click the icon on a card, or the Temperature row on the deal page, to cycle it: not set, hot, warm, cold, back to not set. Each state has its own shape as well as its own colour.

Hot deals that have gone quiet for 14 days or more get their own place on the dashboard's Today panel.

Deal health flags

Baker can check a deal's health and report these flags, and only these:

Flag Meaning
stale Nothing has touched it for 14 days
stuck in stage It has sat in the same stage for 30 days
no next step It has no open todo
overdue todo It has a todo past its due date
missing contact No contact is linked
missing company No company is linked

The dashboard's Needs a touch list shows the stale deals without asking Baker.

The touch-count pill (needs AI)

An estimate of how many real touches a deal has had, read from its notes and activities by an AI model. Under 5 is the dead zone, 5 to 12 is roughly where deals close, 13 and up is a long cycle.

With no AI provider the pill is simply not drawn; there is no error and no empty badge. Where a count exists, the deal page lets you open the line-by-line reasons behind it.

How Top deals are picked

The dashboard's Top deals shows five open deals past the lead stage, ranked by size with probability tipping the order: a deal counts at 40% of its value at 0% probability, rising to its full value at 100%. This is separate from the lead score. If the list is empty while the pipeline is not, every open deal is still a lead.

Which files work

  • CSV (.csv) and vCard (.vcf) always work. No AI is involved and the result is the same every time.

  • 1 MB per file.
  • 5,000 contacts per import.

  • You own every contact you import.

Duplicates are not checked

Import does not look for people already in the CRM. Every row becomes a new contact, even if someone with that email exists. Tidy your file first. See Duplicates.

Duplicates

How to find duplicate records, and why contacts and companies cannot be merged.

Duplicate records are the commonest way a CRM goes stale. CakeCRM helps you avoid them, but it cannot merge contacts or companies, so prevention matters most.

Preventing duplicates

  • Search before you add. Type the name or email in the Contacts or Companies search box first.

Ownership

What a record's owner means, and what it does not.

Contacts, companies, deals and todos each have an Owner.

Owner is not a permission

Owner grants and withholds nothing. Anyone signed in can read, edit, delete and reassign any record, whoever owns it. There are no per-record permissions in CakeCRM.

What owner is for:

  • knowing whose desk a record sits on,
  • filtering a list to one person's work,
  • splitting reports and counts by person.

Unassigned is normal

A record can have no owner, and that is fine. Some records start out unassigned on purpose, such as a company created as a side effect of importing contacts or linking one on a form. Pages show Owner Unassigned rather than hiding the row.

Filtering by owner

The Pipeline has an Owner filter. When your team has more than one person, the Contacts, Companies and simple Todos lists have one too. Each offers an Unassigned choice beside the names.

Changing the owner

Edit the record and pick from the Owner list. It offers Unassigned and every active person. If the current owner has been deactivated, they still show, labelled as such, so opening a form never quietly reassigns the record.

A new contact or company you add starts owned by you. Contacts you import are owned by you.

Owner versus author

The owner is who a record is assigned to. The author is who did a piece of work, such as who logged a call or wrote a note. A colleague's call on your contact is credited to them.

Admins and members

An admin sees exactly the same records as a member. The difference between the two roles is about install settings, not data. See Workspace settings.

GTD basics

The ideas behind the GTD tabs, and the fields every todo can carry.

GTD, short for Getting Things Done, rests on one habit: get everything out of your head into a trusted list, then decide what each item means. CakeCRM's GTD mode is built around that.

The workflow in four steps

  1. Capture everything. Type it into the Add to inbox box at the top of the Todos page. Sort it out later.
  2. Clear the inbox. For each item, decide what kind of action it is and where you can do it. See The Inbox.
  3. Work from your lists. Today shows what is due and starred. To Do shows next actions grouped by context.
  4. Review weekly. The Review tab shows what needs attention.

Quick add

The Add to inbox box understands a few shortcuts. As you type, each one it recognises appears as a chip under the box.

Type Means
#Wholesale File under the project "Wholesale" (created if it does not exist)
@calls Context @calls
! Star it for today
today, tomorrow, next week, in 3 days, friday, aug 15, 8/15, 2026-08-15 Due date
daily, weekly, every weekday, every 3 days, every monday Repeat

Click the ✕ on a chip if it guessed wrong. The words go back into the title. Everything you add this way lands in the inbox. "Today" and "tomorrow" follow the install's time zone, not your computer's clock.

The fields on a todo

  • Status — Inbox, next action, waiting for, delegated, someday/maybe, done or dropped. Dropped means abandoned but recoverable; a todo is never deleted.
  • Context — where or how you can do it, such as @calls, @computer or @errands.
  • Project — an outcome that needs more than one action.
  • Due date — for a real deadline only.
  • Bring back on — hides the todo from your lists until that day, then shows it on Today. It is not a deadline.
  • Repeat — daily, weekdays, weekly, monthly, yearly or every N days.
  • Star — today's priorities. Keep it to a handful.
  • Tags and Notes — anything else.
  • Links — a todo can point at a contact and a deal.

Click a todo's title to open it and change any of these. For long notes, Open larger beside the box gives you a window-sized editor; Save puts the text back, Esc leaves it as it was.

Where a todo came from

A todo nobody typed into the app carries a small label: Baker, Observer (Baker noticed a promise in a conversation and filed it), Capture link or Telegram. Read a Capture link item before you act on it, because anyone with that link could have written it.

What Baker can and cannot do

The honest boundary of what Baker may touch, what it never touches, and what it does with nobody watching.

The short version

Baker can read and change CRM records, work your todos, keep its own memory and knowledge files, search and read connected Gmail, and put drafts in your Gmail Drafts folder. It cannot send email, cannot change install settings, and cannot act outside CakeCRM.

CRM records and todos

Baker can search, create and update contacts, companies and deals, move a deal's stage, mark a deal won or lost, log activities, and create, update and complete todos. Whether each change runs straight away or waits for your Approve depends on the mode you pick. See Approvals.

Deleting a contact or a company is permanent; there is no recycle bin. Deals cannot be deleted at all: archiving is the way to remove one, and it can be restored. A todo is never deleted either: when you ask Baker to delete one, it drops it, and you can reopen it from Done → Dropped.

One turn can make at most 20 changes. Past that, Baker's further changes are refused.

Email

Gmail is read and create-draft only. Baker can search your mail, read a thread and write a draft into your Gmail Drafts folder. It can never send an email. No tool in CakeCRM sends mail, and a test fails the build if one is ever added. You review and send every draft yourself, from Gmail. See Gmail.

By default only admins can have Baker use the connected mailbox.

Settings

Baker has no settings tools at all. It cannot add an AI key, connect Gmail, switch todo mode, define a custom field, add a user or change branding. It can explain how to do these things and point you to the right screen; you do the clicking.

Files you upload

Use Attach a file in the drawer to give Baker a file to read:

  • up to 5 files per message, 10 MB each;
  • CSV, XLSX, MD, TXT, PDF or DOCX.

Only the text is extracted; the file itself is not stored. Uploaded text is treated as untrusted, so for the rest of that conversation every change Baker proposes asks for your approval. Baker cannot attach a file to a record; you add attachments yourself.

When nobody is watching

Baker also runs on a schedule, with nobody in the chat, for the daily digest and nudges about deals and leads that have gone quiet. Those unattended turns are much more limited, and the server enforces it:

  • Baker gets read tools and a single notification, nothing else. It cannot create, update, log or delete anything.
  • It cannot search or open your Gmail, even though those are reads.
  • It sends at most one notification per run.

So the worst a hostile instruction hidden in a note could achieve unattended is one notification.

Roles

Admins and members both get Baker. Baker follows the same rules you do: the server decides what each role may do, and Baker knowing your role only makes its advice accurate, never more permissive.

Three modes

At the bottom of the Baker drawer are three buttons: Read, Ask and Auto. Hover one to see its description. Ask is the default.

Mode What it means
Read Read-only. Baker can look things up but not change data. It is not even offered the tools that change things, and would be refused if it tried one.

What Ask runs straight away

In Ask mode, a change runs without a card only when it stays inside a CakeCRM record, notifies nobody, removes nothing from view, is not a bulk change, and sends nothing outside your install. In practice that means:

  • creating and updating contacts, companies and deals;
  • moving a deal's stage, and marking a deal won or lost;
  • logging an activity;
  • creating, updating and completing todos, and creating or updating projects;
  • setting custom-field values on a contact, company or deal.

A few of those calls still ask, because of what they would do: archiving a contact or company, dropping a todo or project, or setting a bring-back date that hides a todo. Marking a todo done, completing a project, or filing either to someday runs without asking.

What always asks in Ask mode

Deleting, archiving, merging, bulk moves and bulk todo updates, recomputing lead scores, creating a Gmail draft, sending a notification, recording a memory fact, and any change to Baker's protected files. Anything new that has not been classified asks too.

What asks even in Auto

  • Writing Baker's protected files, soul.md and MEMORY.md. These always ask, in every mode, and only an admin can change them. See Memory.
  • A conversation that has read outside content. Once Baker has read an email or an uploaded file in a conversation, every change it proposes asks for approval for the rest of that conversation, even after that message has scrolled out of view. Text someone else wrote can never quietly steer Baker into changing your data.

When Baker wants to make a change that needs approval, its message carries a card naming the action and showing exactly what it will do, with Approve and Deny. Until you answer, nothing has happened.

Open memory takes you to the Memory page. There you can read and edit what Baker knows: its description of itself, its running summary, topic notes, daily logs and the individual facts it has recorded. It works with or without an AI provider.

Baker's memory is shared by the whole team. Anyone can read it. Changing the two protected files, soul.md and MEMORY.md, is for admins only. See Memory.

Todo mode (admins)

Pick one of two buttons:

  • Todo-GTD (default) — inbox, contexts, projects, repeats and a weekly review.
  • Simple list — just todos with due dates and priorities, no inbox or contexts.

Switching is safe and reversible. Both modes read the same todos, and nothing is moved, copied or deleted. The setting applies to everyone. See Todo modes.

No-login links (admins)

The same card controls two links that work without signing in. They show in both todo modes.

Quick capture (write-only) drops text into the inbox and cannot read anything back. It starts with a Public link, and the card warns that anyone who knows the address can add to your inbox. New secret link restricts it. Make public removes the secret again.

Full todo app (read and write) is off by default. Tick Enable the no-login todo app to turn it on. A secret link is made at the same time. New secret link replaces it at once, breaking the old link, including any home-screen app installed from it.

Copy puts a link on your clipboard. These links are shown on this card and nowhere else. Treat them like passwords. See No-login links.

Workspace settings

Admin-only settings for your company name and logo, your team, custom fields, exporting your data, and AI tool connections.

The Workspace tab is for admins only. Members do not see it.

Branding

  • Company name — shown throughout the app.
  • Logo — press Upload logo. PNG, JPEG, GIF or WebP, up to 2 MB. SVG is not accepted. You can remove the logo from the same card.

Press Save branding to keep your changes.

There is no colour picker. CakeCRM has one fixed look, in light and dark. Light or dark is each person's own choice.

Team

Everyone shares one CRM. There are two roles:

  • Admin — can change how the install is set up: branding, team, custom fields, integrations, todo mode and Baker's protected memory files.
  • Member — can do everything else, including working with every contact, company, deal and todo.

Records are the same for both. Owning a record is not a permission. See Ownership.

What you can do here:

  • Add user — email, name, password (at least 8 characters) and role.
  • Change a person's role from the list beside their name.
  • Reset password — set a new password for someone else. An optional box also clears their two-step sign-in, for someone who lost their authenticator. Use it only when needed.
  • Deactivate — stop someone signing in. You can reactivate them later.

Accounts are never deleted, so a past colleague's name still shows on the records they owned. You cannot deactivate yourself, remove your own admin role, or demote or deactivate the last active admin. To change your own password, use Personal settings.

There is no seat limit.

Custom fields

Pick Contacts, Companies or Deals, then + Add custom field. Give it a name and a type: text, number, boolean, date or select. Deleting a field deletes its values everywhere, with no undo. See Custom fields.

Export data

Download CSV export on the Export data card downloads everything in the CRM as one ZIP, with a CSV file per table: companies, contacts, deals and their stage history, activity, todos and projects, notes, custom fields, saved views, Baker's memory, and a users file for looking up owner names. Archived deals are included. Passwords, two-factor secrets, API keys, connection tokens, note attachments and Baker conversations are never exported.

It is a snapshot, not a sync: download again for fresh numbers. Take one before a big change, such as clearing data or a large import.

AI tool connections

Members may connect their own AI tools is off until you turn it on. Admins can always connect. Turning it off stops every member's connection straight away without deleting it, and turning it back on restores them.

The card lists every person's connected AI tools: what each one is, whether it signed in or uses a personal token, whether it is read-only, and when it was connected and last used. Calls shows a connection's log for the last 90 days, and Revoke ends it. See Personal settings for how people connect.

Gmail

Connect one Gmail mailbox so Baker can search and read mail and write drafts. Baker can never send email.

The guarantee

Baker gets exactly two abilities over your mailbox: read and create a draft. It can never send an email. No tool in CakeCRM sends mail, and none may be added: only three mail actions exist, any other Gmail operation is refused, and a test fails the build if a send ability ever appears. Every draft waits in your Gmail Drafts folder for you to review and send yourself.

Who can do this

Setting Gmail up is admin only; members do not see the Integrations section of Settings.

Using it is admin only too, by default. There is one mailbox per install, and Baker offers its mail tools only on an admin's seat. If your team works one shared inbox, an admin can tick Share this mailbox with all seats on the Gmail card to give every member the same access. It is off by default, and it switches itself off again whenever the connection changes, so a newly connected mailbox always starts private.

Connecting

You bring your own Google OAuth app, so your mail never passes through anyone else's project.

  1. Open Settings, Integrations. The Gmail card shows a redirect URI. Copy it.
  2. In the Google Cloud console, under APIs and Services, enable the Gmail API, create an OAuth client (Web application), and add that redirect URI to it.
  3. Paste the Client ID and Client secret into the card and click Save app credentials.
  4. Click Connect Gmail. Google asks you to approve, then sends you back, and the card shows the connected account.

CakeCRM asks Google for two permissions only: read-only mail access, and compose access for drafts. Leave both ticked on Google's screen, or the connection is refused.

If you run CakeCRM behind your own domain or reverse proxy, set BACKEND_URL to your public address so the redirect URI is right. See Deploying CakeCRM.

What Baker can do once connected

  • Search your mail.
  • Read one conversation.
  • Create a draft in your Gmail Drafts folder. In Ask mode (the default) this asks for your approval first; in Auto it runs straight away unless the conversation has read mail or a file. Either way it is only a draft: Baker never sends it.

Email Baker reads is treated as untrusted text. It can never act as an instruction, and once Baker has read mail in a conversation, every change it proposes asks for approval. See Approvals. Baker never runs mail searches on its own schedule; only a conversation with a person in it reaches the mailbox.

What Baker reads, and any draft it writes, is sent to your AI provider as part of the conversation. Attached files in an email are never downloaded; Baker sees only their name, type and size.

Email touches, logged for you

While Gmail is connected, a background job reads recent inbox mail, matches senders to contacts by exact email address, and logs an email touch on that contact, so conversations nobody wrote down still count. It links the touch to a deal only when the contact has exactly one open deal. It needs no AI key. Someone who writes three times with no matching contact raises a single "create a contact?" alert.

Expired or disconnected

If Google revokes or expires access, the card says your Gmail connection expired and offers to reconnect; your app credentials are kept. Disconnect Gmail ends the connection and revokes its access, and also keeps the app credentials for next time.

Telegram

Chat with Baker from your phone. An admin connects one bot for the workspace, then each person links their own chat.

Telegram lets you ask Baker about a deal, log a call or capture a todo from your phone. It has two halves: an admin connects one bot for the whole workspace, and then each person links their own Telegram account to it.

Telegram is a way to reach Baker, so it needs an AI provider connected, apart from quick capture below.

Connecting the bot (admins)

  1. In Telegram, talk to @BotFather and create a bot. It gives you a bot token.
  2. In CakeCRM, open Settings, Integrations, paste the token into Bot token on the Telegram card, and click Connect bot. A bad token is refused.
  3. Tell your team to link their phones.

The token is stored encrypted and never shown again. Connecting a different bot later resets everyone's link, and each person links again.

Linking your phone (everyone)

Go to Settings, Personal, Link my Telegram. If no bot is connected yet, the card says so.

  1. Click Get my link code.
  2. Click Open Telegram to link, which opens a private chat with the bot carrying your code. Or send /link followed by your code in that chat.
  3. The code links the first device that uses it, then expires. Regenerate code issues a new one and releases your current device, which is how you move to a new phone.

Unlink my Telegram ends your link without affecting anyone else. See Personal settings.

Chatting with Baker

Each linked chat is a full conversation with Baker. It sees the same CRM and tools as the drawer in the app, and anything it changes is recorded as you. Telegram chats run in Ask mode: when Baker wants to make a change that needs approval, the message arrives with Approve and Deny buttons, and only your account can press them. See Approvals.

When Baker mentions a deal it looked at, the reply links to that deal on the pipeline board.

Quick capture

In GTD todo mode, a message starting with capture (or /capture) goes straight into your todo inbox without Baker running. It is instant, costs nothing, and works with no AI provider connected. See Todo modes.

What is not supported

  • Group chats. Baker only answers in a private chat.
  • More than one bot per workspace.

Deploying CakeCRM

Run your own CakeCRM, either with the one-click Railway template or on your own machine.

CakeCRM is free and open source (AGPL-3.0), and you run your own copy. It needs a PostgreSQL database and nothing else: no Redis, no object store, no mail server. AI keys are optional and are entered in the app later, never as environment variables.

Deploy to Railway

The quickest route is the Deploy on Railway button in the project README.

  1. Click the button and set AUTH_PASSWORD, the first admin's starting password. It is the only input you provide.
  2. Railway creates the PostgreSQL database and deploys CakeCRM.
  3. Open your CakeCRM address and sign in. Optionally, add an AI provider in the app. See AI setup.

The template supplies DATABASE_URL. JWT_SECRET (which signs sign-ins) and ENCRYPTION_KEY (which encrypts stored keys and tokens) are generated once and kept on the template's persistent volume, so a redeploy does not sign everyone out and stored credentials stay readable. Setting JWT_SECRET yourself is still recommended for production, because a secret you control survives the volume being recreated.

Run it on your own machine

You need Python and Node.js. Then:

git clone https://github.com/wwilson1017/CakeCRM.git
cd CakeCRM
python run.py

run.py asks for an admin email and password, writes a .env file, installs dependencies, builds the app and starts it at http://localhost:8000. If PostgreSQL is not reachable and Docker is installed, it starts the bundled database with Docker Compose. Without Docker, point DATABASE_URL in .env at a PostgreSQL server you already have.

Settings in the environment

Variable What it does
AUTH_PASSWORD Starting password for the first admin. Required.
ADMIN_EMAIL, ADMIN_NAME The first admin's sign-in email and name. Default email admin@cakecrm.local.
DATABASE_URL The PostgreSQL connection string.
JWT_SECRET Signs sign-in sessions. Generated and kept if left unset.
ENCRYPTION_KEY Encrypts AI keys, the Gmail secret and other stored credentials. Keep it stable.
AUTH_PASSWORD_RESET Emergency admin password reset. See First admin and passwords.
HEARTBEAT_ENABLED Baker's scheduled background work. On by default on Railway, off for a local run.
BACKEND_URL Your public address, if you run behind your own domain or proxy. Gmail's redirect URI is built from it, and ChatGPT and Claude sign in to it when people connect their own AI tool (it must be https for that).

The full list, with comments, is in .env.example in the repository.

Good to know

  • Only the backend/data/ folder survives a Railway redeploy; everything else lives in PostgreSQL.
  • The Ollama provider is for your own hardware and is hidden on Railway.
  • To contribute changes back, read CONTRIBUTING.md. Contributions are signed off under the DCO; there is no CLA.

First admin and passwords

How the first admin account is created, how passwords change, and how to get back in when one is lost.

You sign in with an email and a password.

The first admin

On its very first start, CakeCRM creates one admin account. Its email is ADMIN_EMAIL (default admin@cakecrm.local) and its password is AUTH_PASSWORD. The server log on that first start names the email address but never prints the password: read AUTH_PASSWORD from your deployment's settings, or set a new one with AUTH_PASSWORD_RESET (below).

AUTH_PASSWORD is only the starting password. Once you change your password in the app, the new one is what counts, and editing AUTH_PASSWORD later has no effect.

Adding your team

Add people at Settings, Workspace, Team. There are two roles:

  • Member can use the whole CRM: records, pipeline, todos, notes, import, and Baker.
  • Admin can do all of that, plus manage users, AI keys, branding, integrations and the destructive operations.

There is no seat limit. Accounts are never deleted, only deactivated, so a former colleague's name still shows on their records. See Workspace settings.

Changing your password

Go to Settings, Personal, Change password, and give your current password and the new one. The new password must be at least 8 characters. If two-factor is on for your account, the form also asks for a code.

Changing your password signs out every other device immediately; the one you are using stays signed in.

When someone is locked out

  • A member who forgot their password: an admin resets it at Settings, Workspace, Team, then tells them the new one. There is no emailed reset link, because a self-hosted install has no mail server to send one.
  • The admin, or everyone: the person running the server rescues it from the environment.

To rescue the admin account:

  1. Set AUTH_PASSWORD_RESET to a new password and restart. On Railway, adding the variable redeploys, which is the restart.
  2. Sign in as the admin with that password. The logs carry a warning that the reset ran.
  3. Remove AUTH_PASSWORD_RESET and restart again. While it is set, every restart applies it again, so a password you change in the app would not survive.

The reset reactivates the admin account if it was deactivated, turns off its two-factor sign-in, and ends its sessions.

Two-factor sign-in

When two-factor is on for an account, the sign-in screen asks for the 6-digit code from an authenticator app, or a backup code. There is currently no screen in the app for turning two-factor on.
